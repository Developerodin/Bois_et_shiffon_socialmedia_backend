2. **No reporting-currency setting.** Cross-source figures are shown in the **shop's currency** (the currency of the brand's `ShopOrder` rows in the range; several currencies → no figure, with a note). Budgets carry their own currency, chosen when entered (default: the ad account's currency).
3. **Rate for a day** = the latest ECB rate on or before that day (ECB publishes on TARGET working days only). A rate more than 7 days older than the day it serves is **stale**: still used, the figure labelled "uses a rate from <date>". No rate → figures stay per currency (as today).

**Files:** Create `server/data/fx.ts` (client, store, `fx.sync` handler, `rateTable`), `server/integrations/capped-text.ts` (`cappedText(res, maxBytes)`, lifted from `server/shopify/askcart.ts`, which then imports it). Tests `tests/fx.test.ts`, `tests/db/fx.db.test.ts`, `tests/askcart.test.ts` (still green on the lifted helper).

**Data model:**
```prisma
/// ECB euro reference rates: 1 EUR = perEur units of currency on that day (TARGET working days only). Global, not per brand.
model FxRate {
  currency String
  day      DateTime @db.Date
  perEur   Decimal  @db.Decimal(18, 6)
  @@id([currency, day])
}
```

**Interfaces:**
- `ECB_CURRENCIES` constant in `shared/data-sources.ts` (for the budget picker too).

**`sources.ts` changes (generic, additive; other kinds unchanged unless they opt in):**
- `SyncOutcome` gains `settings?: { set?: Record<string, unknown>; unset?: string[] }` and `stopChain?: true`. `recordSync` is the one writer of the patch: one tagged `UPDATE "DataSource" SET settings = (COALESCE(settings, '{}'::jsonb) - ${unset}::text[]) || ${set}::jsonb …` beside its existing write (scoped by id, workspace, brand); keys not named (`reportsIn`, `backfill`, `currency`) are kept.
- `stopChain`: `recordSync` keeps the previous `okAt` (the run isn't a success), status stays ACTIVE, `reason` null; `runDataSync` then returns before the follow-up and chain logic: no retry, no next window, no job queued. Sync now isn't held back (no fresh `okAt`).
- When an outcome's patch **sets** `backfill`, `runDataSync` queues its first window after `recordSync` through `enqueueBackfill(source, plan, { runAt })` (new optional `runAt`, passed to `enqueueSourceSync`). `runAt = now + SPREAD_SECS + spreadSecs(id)`: after today's daily spread, so the chain doesn't hold one of the two `DATA_RUNNING_MAX` slots in the busy hours, and always ≥ `WAIT_MS` so it never overlaps the run that planned it on the same bearer. The same rule for a plan found by a daily run, a manual run or a follow-up; the sweep's restart of a dead chain is queued with no `runAt` today (it runs at sweep time); it takes the same delayed `runAt` (sweep + 2 h + `spreadSecs`), since the same busy-hours reason applies.
- **Window halving** (opt-in per kind: `registerSync(kind, runner, { halveOnCap: true })`, SHOPIFY_ORDERS only): a backfill window that ends `partial` (time cap) after `PARTIAL_RETRIES` is queued again at half its length (`max(1, floor(days / 2))`, retry count reset, key suffix `:h<days>` so the upsert-on-key doesn't swallow it), and the patch sets `backfill.days` to the halved length so a sweep restart keeps it; later windows keep the halved length. A 1-day window that still caps stops as today (the sweep restarts it daily). Rate-limited windows are retried as today, never halved.
- `syncRuns` also returns whether the run is a backfill (`payload.mode`), and `DataSyncRun` gains `backfill: boolean`. `listDataSources` adds `history: { allOrders, visibleSince, through } | null` (SHOPIFY_ORDERS only: from `settings.allOrders`, `settings.visibleSince`, and `syncedThrough` while a plan is set).

**Grant signal (no new mode or key; reuse the backfill chain):**
- **AskCart:** "is `read_all_orders` granted" comes from AskCart's answers, never `grantedScopes`.
